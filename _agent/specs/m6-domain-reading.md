### 3b. Claim engine and pass order (D49)

```python
@dataclass(frozen=True)
class Claim:
    start: int; end: int          # offsets into the text normalize received
    spoken: str                   # §3c wording; only [a-z0-9 .,'-] (checked, §3d)
    rule: str                     # "DOM-1:units", for traces and test messages

@dataclass(frozen=True)
class DomainContext:
    fields: frozenset[Field]
    reading: ReadingSettings
    math_spans: Sequence[tuple[int, int]]
    heading: bool

Claimer = Callable[[str, DomainContext], Iterable[Claim]]
STAGES: tuple[tuple[str, tuple[ModuleType, ...]], ...]   # ("tokens", …), ("numbers", …), ("fields", …)
```

Every claimer belongs to one stage: **tokens** (D49 step 2: whole-token tables, i.e. references,
citations, tickers, gene symbols, `y/y`, `n/m`, HGVS, versions, IPv4, field acronyms), **numbers**
(step 3: currency, units, scientific notation, uncertainty, ranges, ratios, data units, coordinates),
**fields** (step 4: formulas, regnal numerals, clinical shorthand, statistics position, asymptotic
notation). A claimer gated by fields yields nothing unless its table rows' `fields` meet
`ctx.fields` (§3d). `claim_domain` collects the claims stage by stage; a claim that overlaps an already
accepted claim, or any `ctx.math_spans` range, is dropped; within one stage the leftmost wins, then the
longest. Result sorted by `start`, non-overlapping.

Pipeline order inside `normalize(text, *, heading, profile, math_spans)` (signature unchanged; the
context is built from `profile.effective_fields`, `profile.reading` and `math_spans`):

1. D49 step 1 is not in `normalize`: abbreviation dots are protected in stage 5 before `normalize`
   runs (§3f).
2. `claims = claim_domain(text, ctx)` (D49 steps 2–4) runs **before** today's ING-6 pass one.
3. ING-6 pass one (`_PATTERN` loop: citation, et al., percent, URL, e-mail, domain, roman, range,
   phone, clock, hour pair, rating, degrees, times, equals) runs over the text, and a regex match that
   overlaps a claim is not applied; at each claim the loop emits `claim.spoken` with the ING-6
   `emit(s, start, length)` rule, so `char_map` keeps the monotone, inside-the-token mapping of D36.
   So a domain claim wins every conflict with ING-6 (`2019–24`, `51°30′N`, `[2019] UKSC 41`,
   `Henry VIII`), and ING-6 keeps every token no domain rule claims.
4. `_speak_symbols` (D49 step 5) last, unchanged in position; it is a no-op on claim output because
   claim output holds no symbol (`[a-z0-9 .,'-]` only). Mathspeak still calls `normalize` only on prose
   between maths spans, so claims never enter maths spans, and the units inside a maths span stay
   with `mathspeak/symbols.rewrite_units`, which loads the same `units.json` (D48, §3d).
5. SYN-4 and the lexicon in the backend (D49 step 6), unchanged; DOM-25 per-field acronym choices are
   claims in step 2 (§4b).

Test of the order (one per conflict row of the PRD "Shared symbols" table, `test_dom_order.py`).

### 3c. Units grammar (D47, DOM-1, DOM-2, decisions 4 and 5)

A token grammar over the text after a number. `UNIT`, `PREFIX`, `DATA_PREFIX` and
`STANDALONE` are the keys of `units.json` (§3d).

```
quantity    := NUMBER SP? unit_expr                      SP = at most one space or U+202F/U+00A0
NUMBER      := DIGITS ("." DIGITS)? | NUMBER_SCI          (DOM-3 claims the scientific form first)
unit_expr   := STANDALONE | numerator ( "/" denominator )*
numerator   := term ( prod term )*
prod        := " " | "·" | "⋅" | "."                      a space only when the next token is a UNIT
denominator := term | "(" term ( prod term )* ")"
term        := PREFIX? UNIT power?                        PREFIX only where the UNIT row is prefixable
power       := SUP_POW | "^" INT | "^{" INT "}" | ("-"|"−") DIGIT  (glued, no space, DOM-5)
SUP_POW     := "⁻"? [¹²³⁴⁵⁶⁷⁸⁹]+
```

Reading (`speak_quantity`):

- number as written (digits stay digits; the backend's `num2words` reads them), then the unit phrase;
- each term: prefix word + unit word (`k` + `Ω` → "kilohm" by the `fused` table of `units.json`,
  else "kilo" + "ohm" → "kiloohm" is never produced; `eV` with a prefix → "kilo electronvolts" is two
  words per the `units.json` row);
- power 2 or 3 on a unit whose row has `"length": true` → "square"/"cubic" **before** the term, on any
  other unit → "squared"/"cubed" **after** it, any other power → "to the fourth" (ordinal words for
  4..9) after it;
- a negative power moves the term to the denominator; the first denominator term after the numerator is
  preceded by "per"; consecutive denominator terms that came from one parenthesized group or from a run
  of negative powers are joined by a space ("joules per mole kelvin"); each further `/` adds its own
  "per" ("meters per second per second");
- plural (decision 5): the last numerator unit word is plural unless the number is exactly 1;
  denominator words stay singular; a `"invariant": true` row (`molar`, `millimolar`, `hertz`, `lux`,
  `siemens`) never takes a plural; **attributive singular**: when the quantity is preceded by "a" or
  "an" and followed by a lower-case noun, the unit word is singular ("a 2.4 kilobase insert", "a 10
  kilohm resistor");
- unit versus variable (DOM-2): a token is a unit only directly after a NUMBER, not followed by `=` or
  `(`, and, when the block has font runs, set upright; ambiguous letters are decided by the `ambiguous`
  section of `units.json`: `M` after a number "molar" and after a currency symbol "million" (the
  currency case is claimed by DOM-14 in the same stage, leftmost wins); `k` after a currency
  "thousand"; `B` after a DATA_PREFIX "bytes", after a bare count "billion"; `b` "bits";
- micro sign `µ` and Greek `μ`, ohm sign `Ω` and capital omega `Ω` are both accepted;
- a token sequence that does not parse is left untouched (no partial claim).

Every rule above has one test in `test_dom1_units.py` named after it.

### 3e. Role-keyed wordings (D46)

`math_convention.json` goes to `version: 2` with a `roles` section: `{symbol: {role: wording}}`, one
entry per row of the PRD "Shared symbols" table (`→`, `/`, `~ ∼`, `Δ`, `Ω`, `× x`, `°`, `[ ]`, `:`,
`′ ″`, `> <`, `↑ ↓`, `⟨ ⟩`, `*`, `±`), each role named as the PRD names it (`limit`, `after_colon`,
`between_formulas`, `between_nuclides`, `strand`, `grammar`, `between_types`, `unit`, `asymptotic`,
`about`, …). `"default"` is the §3c wording. The existing keys (`"→ (limit or tends)"` and the like)
stay for the M5 checker and are mirrored in `roles`.

`roles.role_of(symbol, left, right, *, span, fields)` decides from: `span` (`maths` or `prose`), the
operand class of the nearest token on each side (`number`, `unit`, `formula`, `nuclide`, `particle`,
`gene`, `type`, `form`, `word`, `none`; classified by `tables.py` lookups, not by guesses), and
`fields` (a field-only role is ignored when its field is off). First matching rule wins; the rule list
is data in `roles` (`"when"` per role), so adding a role is a table edit plus a test. Resolutions
fixed by the decisions: `→` "reacts to form" between formulas, "yields" between nuclides or particles
(decision 3); `/` "per" inside a unit expression (decision 4, by the grammar, not by `roles`); `~` "about"
before a number with no left operand (decision 2); `Δ` "capital delta" except "heat" above an arrow and
`ΔF508` (decision 10); `⟨x⟩` "the expectation value of" for one argument under physics (decision 18);
significance `*` runs counted (decision 12). "goes to" and "nabla" stay banned.

Callers: `_speak_symbols` in `normalize.py` (prose, `span="prose"`) and
`mathspeak/symbols.name_of` (maths, `span="maths"`) both call `roles.wording(symbol,
role_of(...))`; neither keeps its own copy of a role wording.
