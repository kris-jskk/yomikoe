3Four names, one brand

Every request starts with a DNS lookup at the registrar. Each name then goes to its own place. Only yomikoe.app has a host chosen so far.

Why one printed name

Printing only yomikoe.app keeps the brand single; app. and api. are subdomains, free in DNS (D52, PRD Domains table).

Why getyomikoe.com is a rule, not a site

It is a defensive .com. A registrar redirect needs no server and no certificate work on our side (HOST-3, D54).

4How a push becomes the live page

Nobody uploads files by hand. A push to main that touches site/ runs the workflow, and Pages serves whatever the last run uploaded.

Why a workflow and not "deploy from branch"

A branch deploy serves only the repository root or /docs; the page lives in site/, so the workflow uploads exactly that folder and nothing else of the repo becomes a web page (HOST-1, D54).

Why the path filter

Pushes that change only api/ or web/ do not redeploy the landing page; a manual run covers the first deploy (HOSTING.md b.2).

5What the landing page says and where it comes from

The page makes product claims, so each section names its source in an HTML comment. A claim without a PRD row would be marketing nobody can check.

Why the quickstart is local

Until phase 2 hosts the reader, the only working way to use YomiKoe is Docker Compose on the visitor's machine (PRD Domains table, D30).

Why no JavaScript beyond the theme toggle

A static page with no build step is HOST-1; the only script remembers a light/dark choice in the browser.

8What the user does next

These steps are account settings; no worker can do them. Full detail and verify commands are in docs/HOSTING.md.

  1. Confirm D54 (GitHub Pages for the landing page), or name another host.
  2. HOSTING.md b, GitHub Pages: Settings > Pages > Source "GitHub Actions"; merge the branch to main (or run the workflow by hand once); set the custom domain to yomikoe.app; tick "Enforce HTTPS" once the certificate is issued.
  3. HOSTING.md c, DNS at Cloudflare: DNS > Records for yomikoe.app: delete any A, AAAA or CNAME for @, add four A and four AAAA records for @ (values in HOSTING.md, result 1248) with Proxy status DNS only (grey cloud) until the certificate is issued; check with dig and curl -sI https://yomikoe.app. If you later proxy, set SSL/TLS to Full or Full (strict).
  4. HOSTING.md d, redirect at Cloudflare: for getyomikoe.com add proxied A records @ and www to 192.0.2.1, then Rules > Create rule > Redirect Rule: host is getyomikoe.com or www.getyomikoe.com, static target https://yomikoe.app, 301, query string off; check with curl -sI https://getyomikoe.com.
