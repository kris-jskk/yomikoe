HearNarro M5: formulas read aloud, terms said right

Milestone 5 makes HearNarro a study narrator. A paper, a textbook chapter or lecture notes go in; display and inline formulas come out spoken as a person would read them, technical words are pronounced from an academic lexicon and the user's own overrides, code listings are cued, and playback gains an equation repeat, slower equations and pauses after theorems. A document profile decides which rules apply, so "[12]" stays a dropped citation in an essay while "[0, 1]" is read as an interval in a maths text. This page is the live status: one diagram per new mechanism and the phase ledger with evidence.

3Three modes, one engine (Usage modes, VIEW-4)

The student, the technical learner and the book listener use the same pipeline. A mode is a preset: a set of playback and reading settings applied at once. Nothing below the preset knows which mode is on.

Why one engine

The usage modes (PRD, 2026-10-17) differ in pacing and in which blocks are read, not in how text becomes speech; one pipeline keeps one set of evals honest for all three.

What M5 builds of it

The settings the presets need: pauses (SYN-8), equation repeat and speed (PLAY-10, PLAY-11), code cues (ING-10). The preset switch itself is VIEW-4, in M6.

4Document profile (ING-11, D40)

One pass over the finished blocks measures the document, sorts it into a class and stores both in documents.profile_json. Normalization, mathspeak and citation handling take the profile as a parameter, so the eval runner can run any fixture under any class.

Why it is needed

A per-sentence guess cannot tell "[12]" from "[0, 1]" in a paper that uses both (D40). The class carries the document context the guess lacks.

Why a stage-6 pass

The shares are only known once every block is typed; running after the blocks are final keeps stages 1–5 unchanged and lets a class override re-normalize without re-ingesting.

5Mathspeak (MATH-1..4, D36, D37)

A new step after stage 5 rebuilds each expression's structure from the glyphs stage 1 already keeps, speaks it in a standard reading convention, and writes the words into normalized_text with char_map entries. Inline maths inside a sentence (MATH-2) goes through the same step. The backend still receives only words.

Why at ingestion

Speaking maths inside the TTS backend would tie the reading convention to one model and have to be rebuilt for each new voice (D36, SYN-4, SYN-7). Writing words at ingestion keeps the backend unchanged.

Why glyphs first

PDFs carry no LaTeX source; stage 1 already keeps math fonts, sub- and superscript offsets and stacked boxes, so the first engine needs no new dependency or model (D37). Scanned pages use the fallback until MATH-6.

6Code listings (ING-10)

A technical book's listing read aloud as text is noise. Ingestion gives code its own block type, the default speaks a short cue, and a toggle (after M5, with TERM-5) reads it line by line. Inline code inside a sentence is read as its words.

Why it is needed

The technical-learner mode (Usage modes) works through books with listings; without a type, a listing is read as broken sentences of symbols.

Why a cue by default

A listing is studied by eye; the cue says it is there and how long it is, and the board (VIEW-1, M6) shows it.

7Pronunciation chain (TERM-1, TERM-2)

Every word the voice will say is looked up in a fixed order; the first source that knows the word decides. The user's own choices come first, the shipped academic lexicon comes before the backend's general one, and the fallback guess comes last.

Why this order

The user knows their field best (TERM-2); a term the document defines itself comes next, as acronyms already do; the academic lexicon (TERM-1) covers what a general voice lexicon gets wrong.

Why the cache is part of it

An override that does not reach already-synthesized audio would leave the old pronunciation playing; invalidation is in the requirement (TERM-2, SYN-6).

8Playback additions (PLAY-10, PLAY-11, SYN-8, MATH-5)

Playback stays per-segment HTTP fetch plus Web Audio buffers scheduled on one clock (D5), driven by the one reducer (D10). The three additions only change when a buffer starts and how long it lasts.

Why it is needed

A spoken formula is dense; the student needs to hear it again or slower without losing their place in the sentence stream (PLAY-10, PLAY-11), and a pause after "Theorem 2.1." marks the statement (SYN-8, MATH-4).

Why on the same timeline

Highlighting, skip and resume already depend on one scheduled clock and one reducer (D5, D10); a second playback path would split them.

Licence survey outcome (D37)

  • M5 builds its own rule engine over the glyphs: nothing to license, CPU only.
  • Optional later: MathML from the glyph structure, spoken by MathCAT (MIT) or Speech Rule Engine (Apache-2.0, needs Node).
  • Scanned pages later (MATH-6): Pix2Text MFR weights (MIT) run without the pix2text package, or UniMERNet once its weight licence is confirmed.
  • Excluded: Nougat weights (CC-BY-NC), pix2tex weights (reported CC BY-NC-SA, unverified), the pix2text package (AGPL-3.0 through doclayout-yolo).
